## Historia de usuario

**Como** integrante del equipo de desarrollo,  
**quiero** un repositorio con flujo de trabajo, plantillas y tablero definidos,  
**para** trabajar de forma ordenada y trazable durante todo el curso.

## Criterios de aceptación

- [ ] **CA1:** Dado el repositorio, cuando reviso la raíz, entonces existe un .gitignore adecuado a Python y Azure.
- [ ] **CA2:** Dado un nuevo issue, cuando elijo la plantilla Historia de usuario, entonces se crea con el formato «Como…, quiero…, para…», criterios y checklist.
- [ ] **CA3:** Dado un Pull Request, cuando lo abro, entonces se carga la plantilla de PR y se valida el título con commits semánticos.
- [ ] **CA4:** Dado GitHub Projects, cuando abro el tablero, entonces las historias aparecen agrupadas por Milestone.

## Tareas técnicas

- [ ] Crear .gitignore
- [ ] Documentar estrategia de ramas y commits en CONTRIBUTING.md
- [ ] Crear plantillas de issue y Pull Request
- [ ] Proteger la rama main
- [ ] Crear etiquetas, milestones y tablero
- [ ] Registrar el backlog inicial
- [ ] Documentación actualizada

## Definición de terminado (DoD)

- [ ] Código revisado mediante Pull Request
- [ ] Pruebas automáticas en verde en GitHub Actions
- [ ] Criterios de aceptación verificados
